Security and data

Last updated: November 27, 2026

Runs on Atlassian. Afterdone is built on Atlassian Forge and runs only on Atlassian infrastructure. Your Jira and Confluence content never leaves Atlassian: no external servers, no Forge Remote, no outbound network permissions.

Architecture

  1. A Jira event fires when an issue or Epic moves to a Done status, or when a version is released.
  2. The App puts a job in a Forge async queue, so the work happens in the background in small batches.
  3. The job reads the issue and the Confluence pages linked to it or that mention its key.
  4. The App asks the Forge LLMs API, provided by Atlassian inside Forge, which sentences on the page contradict the Jira work.
  5. Results are saved in Forge storage (KVS) of your site and shown in the Drift Report admin page. Optionally, Jira emails the issue's reporter and assignee.

Every step uses Atlassian-hosted compute, storage, and model services. We operate no servers or databases for the App.

Permissions (scopes) and why we need them

ScopeWhy
read:jira-workReceive issue and version events; read the fields, comments, and links of the issue that reached Done; find Done child issues of an Epic and Done issues in a released version.
write:jira-workSend the conflict email to the issue's reporter and assignee through Jira's built-in notify API. The App does not edit issues.
read:page:confluenceRead the text and version of the pages linked to the issue.
search:confluenceFind pages that mention the issue key.
storage:appSave findings and usage counters in Forge storage.

The App acts with the App's own Forge identity. It does not write to Confluence and does not change page permissions. It only sees pages that the App user can see in your site.

Data handling

DataWhyWhere it lives
Jira issue fields: key, summary, type, status, resolution, fix versions, description, latest comments, remote links, and the summaries of Done child issues of an EpicTo know what was actually deliveredRead at check time, not stored, except the issue key, summary, and status saved with a finding
Confluence page ID, title, URL, version number, and body text of pages linked to the issue or that mention its keyTo compare the page with the Jira workRead at check time. Only page ID, title, URL, version, and the quoted sentences are stored with a finding
Findings: the conflicting page sentence, the Jira evidence, a short explanation, severity, review status, and timestampsTo show the Drift ReportForge storage (KVS) of your installation, deleted automatically after 180 days
Usage counters: checks run, tokens used, checks skipped, per monthTo enforce the monthly check cap and show usageForge storage of your installation
A hash of each issue and page pairTo skip pages that did not change since the last checkForge storage of your installation
  • Storage location: Forge storage of your Atlassian site, managed by Atlassian, following Atlassian's Forge data residency rules.
  • Encryption: Atlassian encrypts Forge storage at rest and all traffic in transit. See Atlassian's Trust Center.
  • Retention: findings expire after 180 days; App storage is removed by Atlassian after uninstall.
  • Logs: technical logs (issue keys, page IDs, error codes, counts) stay in Atlassian's developer console. No page text.
  • Model training: the App does not use your data to train any model.
  • No secrets: the App does not store or access passwords, API tokens, or personal access tokens.
  • Sub-processors: none outside Atlassian for App data.

Access

We have no routine access to your Jira or Confluence content or to findings stored in your site. To investigate a problem, we may ask you for a screenshot or an issue key; we never ask for credentials.

Development practices

  • Least privilege: only the scopes listed above, reviewed before each release.
  • No outbound network access, verified with Atlassian's Runs on Atlassian eligibility check before each production release.
  • Source code in a private repository with two-factor authentication on developer accounts.
  • Dependencies kept up to date; security advisories reviewed before release.
  • Guardrails against model errors: a finding is kept only if its quoted sentence appears on the page.
  • Cost and abuse guard: a monthly cap on model checks per site.

Report a vulnerability

Email security@getafterdone.com. We acknowledge reports within 2 business days and will keep you informed while we fix the issue. Please give us reasonable time to fix it before disclosing it publicly, and don't access data that isn't yours.
